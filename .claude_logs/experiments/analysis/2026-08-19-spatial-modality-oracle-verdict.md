# Spatial-Modality Oracle 판정 — 게이트 발화, 상계 과대 → 실현성 통제 선행 (2026-08-19)

> 실측 = 모니터링 세션(yeon GPU4,5), 대표 ckpt P46 C3-only λ0.1 ep70(67.79), M=4. 도구 `tools/oracle_spatial_modality.py`(develop, 스모크 독립 재검증됨). 판정 = discussion 세션(fable).

## 1. 수치

| split | mIoU(full 4모달) | mIoU(oracle) | Δ |
|---|---|---|---|
| val | 67.803 | 76.463 | **+8.660** |
| test | 55.912 | 64.197 | **+8.285** |

- 사전등록 게이트(§3: <0.3 폐쇄 / 0.3~1.0 경계 / **≥1.0 여지실재**)를 **8배 초과** → 기계적으로 "여지실재" 분기.
- **S\* 분포**: 채택 부분집합의 val 97.8%/test 96.0%가 **단일모달**, full(4모달) 채택 ≈0.01%, no-correct-subset val 1.4%/test 3.0%.
- per-class 상위 Δ: val Ground +19.38·Pedestrian +14.41·Fence +14.30 / test Wall +27.54·Fence +20.11·Terrain +17.81 (thin/혼동 클래스 집중).

## 2. 판정 — 내 사전확률이 틀렸다(인정), 단 상계가 너무 느슨하다

**2a. 사전등록 예측(Δ<0.3, 축 폐쇄)은 반증됐다.** 구체적 추론 오류 = **"전역 drop-modality ≈0 ⟹ 픽셀별 라우팅 여지 0"의 함의가 거짓.** 전역 평균이 평평해도 픽셀마다 국소 최적 모달이 다르면 평균에서 상쇄돼 보인다. **전역 모달-ablation 평탄 ≠ 국소 모달 상보성 부재** — 논문 회수 가능한 통찰(모달 잉여 서사를 국소/전역으로 분리해야 함).

**2b. 그러나 게이트 발화 ≠ 라우터 정당화.** 이 오라클은 CEA(H4)보다 **훨씬 느슨한 상계**다:
- **union-over-15 팽창**: "픽셀마다 15개 중 하나라도 GT 맞으면 성공"은 무편향·고분산 예측기를 겹칠수록 통계적으로 무조건 상승. CEA는 조건 소수 + held-out 전문가(타이트)였으나 이건 픽셀별 15자유선택(느슨). +8.5의 상당분이 팽창일 수 있음.
- **zero-fill = OOD 입력**: 부분집합 예측은 "4모달 학습 모델에 일부 모달 0-채움" — 학습 시 거의 못 본 입력이라 예측이 인위적으로 요동 → 오라클 **추가 팽창**. 별도 단일모달 학습이 아님(학습 0).
- 따라서 **S\* 단일모달 96% 지배도 "융합이 정보 훼손"으로 확정 불가** — 저입력·고분산 예측기가 union 복권에 더 자주 당첨되는 것과 관측상 구분 안 됨. (단, 단일모달은 15개 중 4개뿐인데 96% 채택 = 비균등 선호라 "무언가 있음"의 약한 힌트는 됨.)

**2c. 결론**: **spatial×modality 축은 닫히지 않았다**(H16 잠정 재개방, SoftMoE 재제안 금지 잠정 해제). 그러나 +8.5를 **팽창 바닥 vs 실현 가능 구조**로 분리하기 전엔 라우터 착수 금지. 분리 = 아래 통제(순수 numpy 후처리, 캐시 재사용 → GPU 불요).

## 3. 후속 통제 (사전등록, 캐시된 예측맵 재사용)

| 통제 | 방법 | 판정 |
|---|---|---|
| **선택 입도 스윕** | 픽셀별 선택 → B×B 블록(8/16/32/64) 단위 상수선택 강제 후 오라클 Δ 재산출 | Δ가 16px에서 **<1.0로 붕괴 → 픽셀노이즈(실현 불가)** / 32px에서도 **≥2 유지 → 공간응집(실현 가능)** |
| **독립성 널** | 각 부분집합 정답맵을 정확도 보존한 채 공간 셔플(전역 또는 이미지내) N회 → 오라클 Δ 기대치 = 팽창 바닥 | 관측 Δ ≈ 널 → **전부 팽창(축 폐쇄, H16 반증)** / 관측 − 널 ≥ 몇 pt → **진짜 구조 = 그 값** |

**통합 게이트(사전등록)**:
- 블록16 Δ < 1.0 **AND** 관측 ≈ 독립성널 → +8.5는 팽창, spatial 라우팅 실현 불가 → **H16 최종 반증**(SoftMoE 폐쇄 재확정) + 방법론 노트("값싼 픽셀 오라클은 오도하는 스크린").
- 블록16 Δ ≥ 2.0 **AND** 관측 ≫ 널 → **진짜 공간응집 구조 실재** → §5 레버로 실제 라우터 설계(별도 제안, full run).

구현 = `oracle_spatial_modality.py`에 `--select-granularity {1,8,16,32,64}` + `--null-shuffle N` 플래그 추가(합성 단계만, forward 재실행 0). labcode 위임 + 검수. 캐시 = yeon `drone-MemorySAM-p49/oracle_probe_out/deliver_c3only_lam01_ep70/`.

## 4. 원장/계획 반영

- **H16**: ✗/✓ 아님 → **⏳ 잠정 재개방**(스크린 통과, 실현성 통제 대기). "적응 가설 계열 폐쇄"(종합 §1)에 **단서 부기**: 조건축(CEA)은 타이트 상계로 닫혔으나 **공간축은 스크린 미폐쇄** — 통제 결과에 따라 종합 문구 갱신.
- plan #13 = 완료(판정), 후속 통제 = #14 신설.
