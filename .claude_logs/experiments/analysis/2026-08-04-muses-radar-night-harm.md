> 근거: 공식 Codabench test 두 제출의 조건별 대조. 판정 = opus 세션. 수치는 제출 결과 원문.

| 제출 | 모달 | 공식 test |

## 3. 배제된 설명 — 디코딩 불일치 아님

ISSUE-025(radar를 lidar 디코더로 폴스루) 재발을 의심했으나 **아니다**:
- 학습 로더 `semseg/datasets/muses.py:_open_radar` = 픽스본(`RADAR_RANGE_MAX=150.0`, 채널 `[range/150, intensity/255, occupancy]`).
- 제출 추론은 `tools/predict_muses_test.py --radar-decode fixed` → `legacy_radar=False` → **같은 `_open_radar`**.
- 4모달 seed2 학습 시작 07-28 > ISSUE-025 픽스 07-21.
→ 학습·추론 디코딩 **일치**. 원인은 데이터 코덱이 아니라 **학습/융합** 쪽이다.

## 4. 기제 가설 — "RGB가 약해질 때 가장 정보 없는 모달로 폴백한다"

- radar는 실측상 **3번째 채널(height)이 전 픽셀 정확히 0**이라 코드가 `occupancy` 마스크로 대체했다(`muses.py:203-217` 주석). 즉 실질 정보는 range + intensity 2채널의 희소 투영뿐이며, **semantic 변별력이 구조적으로 낮다**.
- 야간에는 img의 reliability가 떨어져 P36 router가 가중치를 다른 모달로 옮긴다. 그 폴백이 **정보가 가장 적은 radar로 흘러가면** 유용한 lidar/event 증거를 밀어낸다.
- 조도가 낮을수록 손해가 커지는 관측(clear_night −2.4 → fog_night −5.4)과 정합한다. **radar 자체가 조도 무관인 센서이므로, 야간에만 손해가 나는 것은 센서 물리가 아니라 라우팅/학습 현상이다.**

## 5. 직접 측정 수단 — 이미 배치돼 있다

**P47-2(Uni-modal Balance)의 per-modal accuracy 로그**가 이 가설의 직접 검증기다. 모달별 독립 head가 각자 GT를 얼마나 맞히는지 찍으므로, **radar의 uni-modal acc가 바닥이면 "정보 없음"이 정량 확정**된다.
- 3모달 arm(jarvis, 진행 중)에는 radar가 없으므로 확인 불가.
- **4모달 arm(hpca100, P47-1 완주 후 배치 예정)의 ep30 즉검에서 최우선 확인 항목**으로 둔다.

부가 검증(비용 낮음, GPU 여유 시): 4모달 ckpt로 **drop-radar를 day/night 분리 측정**. 가설이 맞으면 dMIoU가 **야간에서 훨씬 크게 양수**여야 한다(현 전체 +0.13은 주·야 상쇄된 값일 가능성).

## 6. 함의

1. **"radar 무익" → "radar는 주간엔 소폭 유익, 야간엔 유해"로 판정을 정밀화한다.** 기존 결론(전체 −0.217)은 상쇄된 합계였다.
2. 처방은 **추론 시 모달 재가중이 아니다**(반증된 경로 + 조건 라벨 외부신호 금지). 학습 시 개입 = P47-2 계열이 맞다.
3. 논문 관점: "모달을 늘리면 나빠진다"는 리더보드 현상에 **조건 해상도의 증거**를 붙일 수 있다 — 단순 희석이 아니라 **약한 모달로의 폴백**이라는 구체적 기제.
