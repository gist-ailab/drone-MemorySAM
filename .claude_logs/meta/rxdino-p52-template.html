RxDINO: Self-Prescribing Training for Multimodal Segmentation

2026-09-01 · ⚠️ P52 본런 미실시 — 방법·근거·실험계획 문서 (구성요소 증거는 완료, §3에 구분 명시)

초록 — 멀티모달 세그멘테이션 연구는 "모달을 더 잘 섞는" 융합 모듈 경쟁이 지배하지만, 우리는 통제 소거 실험으로 그 전제가 강한 frozen 백본 위에서 성립하지 않음을 보인다(선택·attention·평균·저랭크 결합 4갈래 전부 무익~유해). 성능을 실제로 움직이는 축은 학습 신호와 초기화다. 이에 우리는 RxDINO를 제안한다: 하나의 미니멀 frozen-VFM 아키텍처 위에서 ① 어댑터-만 정렬 사전학습으로 초기화하고 ② 학습 중 계산되는 병리 지표(클래스 붕괴·모달 게으름)가 학습-전용 처방의 강도를 스스로 조절한다. 벤치별 설정 차이는 없으며, 데이터셋별 거동은 λ 궤적으로 창발한다. 주행(DELIVER·MUSES)과 재질(MCubeS)의 이질적 센서 셋에서 단일 레시피로 검증한다.

1. 기존 문제

P1 — "잘 섞으면 오른다"는 미검증 전제

CMX → CMNeXt → GeminiFusion → CrossWeaver로 이어지는 계보는 매번 더 정교한 융합 모듈을 제안한다. 그러나 강한 frozen 백본 위에서 이 전제를 통제 검증한 결과(동일 백본·레시피·시드, 융합부만 교체): 선택/라우팅은 원리적으로 불가(남은 보완정보가 anti-consensus — 다수가 틀린 곳에서만 소수가 옳고, 합의·신뢰도 어느 신호로도 표시 안 됨), cross-attention은 −2.05(파라미터 15.9×), 학습형 게이트 융합은 산술평균과 동급, 인코더-내 저랭크 결합은 −0.82. 즉 믹서는 병목이 아니다.

P2 — 벤치별 숨은 튜닝: "단일 메서드"의 부재

실무적으로 모든 방법이 데이터셋별로 손실·하이퍼파라미터를 조정하지만 논문에는 드러나지 않는다. 우리 자체 실측이 왜 이것이 문제인지 보여준다: 클래스축 처방(prototype 손실)을 고정 강도로 적용하면 붕괴가 있는 DELIVER에선 +1.4지만 없는 MUSES에선 −0.77로 해롭다. 병리는 벤치마다 다른데, 처방을 벤치별로 사람이 켜고 끄면 그것은 단일 메서드가 아니다.

P3 — 어댑터의 정렬 부재

frozen 백본 + 모달별 어댑터 패러다임(MLE-SAM 등)에서 어댑터·융합부는 타깃 데이터 수천 장만으로 from-scratch 학습된다. VLM 연구의 교훈("커넥터 선택은 부차적, 정렬 사전학습이 1차")이 센서 도메인에는 이식되지 않았다.

2. 해결 방법 — RxDINO

2.1 전체 구조

추론 경로(①→⑤)는 의도적으로 단순하다: 공유 frozen 백본 + 모달별 LoRA → 미니멀 융합 → FPN 디코더. 모든 제안 요소는 학습 시에만 존재한다(점선) — 위쪽의 자기-적응 처방 2종과 아래쪽의 정렬 사전학습.

{{FIG1}}

Fig. 1 — 전체 개요. 실선 ①~⑤ = 추론 경로(3벤치 동일 그래프). 녹색 점선 = 학습-전용 자기-적응 처방(추론 시 폐기), 보라 점선 = 초기화 전용 사전학습. 색 = frozen(파랑)/trainable(주황)/train-only(녹)/init-only(보라).

블록구성왜 (근거)
② 인코더DINOv3-L 24블록 동결(304M) + 모달별 LoRA(Q/V, r16, ~수 M)백본이 계보 최대 변수(+11.6)이나 L 초과는 포화(+0.18) — 사되 파괴하지 않는다. 학습분 ~50M로 소비자 GPU 학습 가능
③ 융합gated-MLP(γ=tanh(0.1)) + VICReg(var+cov)믹서 4갈래 소거(P1)가 미니멀리즘을 정당화. VICReg은 lidar 유효랭크 4.7→78+ 복원 실측
④ 디코더SimpleFPN(4스케일) + 픽셀 헤드 (+M2F-lite aux, 학습 전용)표준 구성 — 기여 주장 없음

2.2 처방 A: C3-adaptive (클래스축)

{{FIG2}}

Fig. 2 — C3-adaptive. ① 학습 배치의 혼동을 EMA로 누적 → ② 오답이 한 클래스로 집중되는(=흡수되는) 클래스만 높은 점수 s_c — "그냥 어려운" 클래스(오답 분산)와 구분됨 → ③ 점수에 비례한 강도 λ_c로 그 클래스 특징만 자기 prototype으로 되당김. 건강한 클래스는 압력 0, 전 클래스 붕괴 시 균일 λ(고정팔)와 동일해지는 상한 구조.

2.3 처방 B: UniBal-adaptive (모달축)

{{FIG3}}

Fig. 3 — UniBal-adaptive. ① 각 모달이 경량 head로 "혼자" 세그를 시도 → ② 혼자 유난히 못 푸는 모달 = 융합 뒤에 숨어 학습이 안 된 게으른 모달 → ③ 그 모달에만 uni-modal CE를 강화(λ_u ∝ 게으름). head는 학습 후 폐기. 학습-내 모달 기여 측정→변조는 OGM-GE(CVPR'22)로 검증된 계열.

2.4 초기화: 정렬 사전학습

{{FIG4}}

Fig. 4 — 정렬 사전학습. RGB-만 웹 코퍼스에서 가짜 센서 6종을 유도(전부 proxy 명시) → 한 모달을 가리고 다른 모달로 복원하는 숙제로 어댑터+융합부가 모달 대응 구조를 선학습 → 가중치만 본학습의 출발점으로 이식. 매칭-시드 통제로 +0.74~+1.38 실측(이득은 조기 수렴 국면 집중 → 조기정지와 결합).

2.5 무엇이 새로운가 (경계 명시)

  • 주장: ① 병리 지표가 처방 강도를 온라인 조절하는 자기-처방 학습(클래스축+모달축 통합, 벤치별 config 0) ② frozen-VFM 위 어댑터-만 정렬 사전학습 ③ 믹서 무용의 4갈래 통제 소거 + anti-consensus 규명(설계 정당화).
  • 주장 안 함: frozen 백본+모달별 LoRA(MLE-SAM 선점) · 융합 모듈 자체 · adaptive loss weighting 일반 개념(선례 존재 — 우리는 병리-특이 지표와 3벤치 창발 검증이 차별).

3. 실험 — 본런 미실시 무엇이 들어가야 하나

4. 설계 고민 — 모달리티별 LoRA가 최선인가?

정직한 답: 최선이라고 증명된 적은 없다 — "검증된 기본값"일 뿐이다. 우리 모든 실적이 per-modal LoRA 위에서 나왔지만, 구조 대안과의 통제 비교는 한 적이 없다. 선택지와 증거:

구조장점약점/위험우리 증거와의 관계
A. per-modal 독립 (현행)모달 통계 이질성(희소 lidar vs 조밀 RGB) 흡수 · 실적 전부 이 위에서모달 간 공유 구조를 학습으로만 획득 — 정렬이 안 돼 있음P50(+0.74)이 바로 이 약점의 사후 보정이었다는 해석 가능
B. 완전 공유 1개파라미터 최소 · 정렬 공짜모달 특이성 소실 위험(lidar 희소성 등)미검 — 프로브 가치 있음
C. 공유 + per-modal 잔차 (r8+r8)공통 부분공간(정렬 내장) + 특이성 유지 — P50과 같은 목표를 아키텍처로 달성구현 복잡도 소폭 · rank 배분 새 하이퍼파라미터문헌 선례(shared-specific 분해, MultiLoReFT류) · 가장 유망한 대안
D. 입력-조건부 단일(라우팅형)—라우팅 계열 — 우리 원장에서 반증 인접(H1/H16)재시도 비권고

권고: 본런(E1)은 A로 간다 — 검증된 레시피를 바꿔 본런을 도박으로 만들지 않는다. 대신 E-LoRA ablation을 사전등록한다: A vs B vs C, 파라미터 매칭·시드 매칭, DELIVER 프로브 1벤치. 예측 — C가 A와 동급 이상이면 "정렬을 아키텍처에 내장"으로 채택 검토(사전학습 P50과의 중복/시너지 해석 포함: C+P50 > A+P50이면 두 정렬 기제가 상보, 동급이면 중복). C의 이득이 없으면 A 유지가 실증으로 정당화된다 — 어느 쪽이든 논문 ablation 행.
