# 고해상 특징이 실제 열화를 토큰 단위로 알아보는가(학습 0) — P56-C 기각의 원인('신호 없음')이 고해상 경로에서 해소되는지 재검

- id: DRN-261028-01
- kind: analysis
- 문제(PRB): PRB-DRN-261020-01
- 질문: A2 의 센서별 고해상 s4 특징 토큰 통계가 DELIVER 의 실제 열화 파티션(RGB 모션블러·과노출·저노출, LiDAR 지터, Event 저해상)을 clean 과 가르는가? P56-C 가 썼던 블록 6 저해상 통계와 얼마나 다른가?
- 가설: H: 고해상 s4 통계(토큰별 노름·고주파 에너지·채널 분산)는 실제 열화 5파티션 중 ≥3 에서 AUROC ≥ 0.8, 블록 6 통계는 Q1d 수준(≤0.76). 성립하면 토큰 적응 LoRA 제어의 입력 신호가 존재한다는 뜻이고, P56-C 의 붕괴(α std≈0)는 신호 부재 때문이었다는 해석이 선다
- 바꾼 변수(change): 학습 없음. A2 s821 ckpt, DELIVER test 전수. 센서별 고해상 경로 출력(hires_adapter 의 센서별 스템 출력 또는 s4 레벨, 센서 분리 가능한 지점에서 추출)과 블록 6 토큰 특징을 토큰별 통계 3종으로 요약 → 파티션(clean vs 열화) 이진 AUROC(이미지 단위·토큰 단위 둘 다), 센서별. 기존 도구 tools/oracle_headroom_probe.py·Q1d 품질 헤드 프로브 코드를 확장(새로 짜지 않음)
- 기준선: Q1d(2026-09-29) 품질 헤드 AUROC: 모션블러 0.46·과노출 0.76·저노출 0.76·야간 0.28·안개 0.44
- 성공 기준: 표: 신호원(고해상 s4 / 블록 6) × 파티션 5 × 센서 → AUROC. 통과 = 고해상이 ≥3 파티션에서 ≥0.8 이고 블록 6 보다 ≥0.15 높음. 통과 시 method 가 '고해상 통계 구동 토큰 적응 LoRA(A2+P56-C 라우터, 입력 교체)' 1시드 스크린을 별도 사전등록
- 반증 조건: 고해상 통계도 ≤0.76 이면 토큰 적응 LoRA 축을 신호원과 무관하게 종결(반복 금지 목록에 기록)
