MCubeS 체크포인트 선택 규칙 판단 요청(DRN-261027-01 / MCubeS A2 DRN-261017-02 기동 전).
사실: semseg/datasets/mcubes.py:142 의 _get_file_names 는 split='val' 이면 list_folder/test.txt(102장)를 읽는다. 즉 학습기 "val-best" 체크포인트가 MCubeS 에서는 test 102장으로 고른 것이 된다. 원 논문(Liang et al., CVPR 2022, 7쪽)의 분할은 train 302 / val 96 / test 102 이고, 96장 val 은 지금 학습·선택 어디에도 쓰이지 않는다.
원고 §3 은 "test 로 체크포인트를 고르지 않는다"고 적고 있어 MCubeS 에서는 사실과 맞지 않는다(원고에 todo 로 표시함).
선택지: (a) MCubeS A2 기동 전에 선택용 split 을 val 96장으로 바꾼다(로더 수정 → 하네스 재동결 필요, 공정성상 기준선 수치와 비교 방식도 적어야 함) (b) 커뮤니티 관행(StitchFusion 등 test 102 로 보고)을 따르고 원고에 "MCubeS 는 관행대로 test 로 선택"이라고 명시 (c) 최종 에폭 체크포인트를 보고.
기존 MCubeS 헤드라인(P39.1 58.07, headline.yaml "학습기 val-best")도 같은 문제를 가진다. MCubeS A2 가 아직 미착수이므로 기동 전에 정하는 것이 비용이 가장 적다.
