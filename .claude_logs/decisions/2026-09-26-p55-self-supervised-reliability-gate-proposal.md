# P55 — 외부 레이블 없는 자기감독 모달 신뢰도 게이트 (제안 초안)

## 0. user 요구 (2026-09-26, 원문 요지)
- DGFusion·CAFuser 등 선행 융합은 **외부 신호**(언어·조건 라벨, LiDAR depth 재구성 감독)로 융합 가중을 정한다.
- 우리는 **네트워크가 스스로 모달 품질을 분석해 어디를 더 볼지 동적으로 학습**하는 것을 메인으로 삼는다.
- 과거 게이팅 반증이 SAM2 인코더에서만 나온 것은 아닌지 확인하고, 선행 연구를 적용하면 어떻게 되는지 본다.

## 1. 근거 세 갈래 (2026-09-26 조사, Fable 문헌 인용은 원문 재확인 전 — 특히 2606~2609 번호)

### 1-1. 우리 반증 기록의 인코더 대조 (내부 문서 전수)
- 반증 26건 중 13건이 SAM2(P8~P33)에서만 시험됐다: GT 오라클 감독 게이트(P10) · MI 라우팅(P11) · 조건부 SoftMoE 게이트(P12·P20·P29, 가중 ≈균등으로 굳음) · 에너지/엔트로피 가중(P13~P17) · 공간 품질 게이팅 SQG(P24~P27, 버그 ISSUE-013·학습 부족으로 미완) · CG-MoD(P33).
- DINOv3 에서 반증: 학습 없는 신뢰도 편향(RBMA·CoRB), 추론 게이트·보정, 클래스 라우터(P36·P37a), zero-init 잔차(P38·P39.1·P49), 공간 라우터(H16), gated 트렁크(H21), 모달 기울기·손실 재가중(P44·P47-2·P52), 합성 열화 라벨 품질 헤드(Q3).
- **"모델 자신의 오차로 감독되는 공간 게이트"는 SAM2 에서만(그것도 미완) 시험됐고 DINOv3 에서는 한 번도 시험되지 않았다.**

### 1-2. 게이트 실패는 인코더 탓인가 → 대체로 아니다
- 게이트 실패는 MiT·SAM2·동결 DINOv2 모두에서 반복된다(MLE-SAM 2412.04220: SAM2+LoRA+MoE 라우터도 DELIVER event 단독 0.74·LiDAR 단독 2.07). 공통 원인 = **게이트의 목표·학습 분포**.
- DELIVER 에서 event·LiDAR 무시는 분야 전반 현상(2503.18445: RD≈RDEL). 이론상 depth 와 공선인 모달은 학습되지 않는다(2312.00935).
- DINOv3 특유: 색·감마·블러에 둔감하도록 학습된 특징이라 **깊은 토큰만 보는 품질 헤드는 광학 열화를 못 본다**(Q1b-2 AUROC 0.67~0.73 과 일치). 광학 열화는 얕은 층 주파수 통계·모달 간 일치도로 잡힌다(2606.01173 SAFER-DEIM, 2607.04587 RAF).

### 1-3. 선행 연구와 노벨티
- "네트워크가 스스로 품질을 추정해 게이팅"하는 **개념 자체는 새롭지 않다**: CMX FRM · CMNeXt SQ-Hub · TokenFusion · GeminiFusion · RSGMamba(2604.12319, 불확실성 × 일치도 토큰 게이트) · MAGIC 선택.
- 벤치 증거는 오히려 불리하다: 게이트형(CMNeXt·GeminiFusion·TokenFusion)이 **가장 덜 강건**하고, 게이트 없는 균형 학습(EQUISeg 2509.24505·RMMSS 2505.12861·AnySeg 2411.17141)이 가장 강건하다. CAFuser 스스로 "학습된 정적 가중 = 평균"을 보고했다.
- **비어 있는 칸**(정직한 노벨티 후보): ①외부 레이블 없이 **열화에 보정된 토큰 단위** 신뢰도(GIML·QMF·ReliFusion 은 전역, 분할 아님) ②동결 파운데이션 백본 위의 **모달 간 일치도 공간 신뢰도 지도** ③DGFusion·CAFuser 를 넘는 외부 레이블 없는 게이트(아직 없음). 노벨티는 "아이디어"가 아니라 **보정 기제 + 토큰 단위 + 게이트가 정적이 아니라는 증거(치환 검정)** 로 주장해야 한다.

## 2. 설계 (Q2 레시피 위에 얹는다)
1. **바탕 = Q2**(모달 dropout + 열화 두 패스 + 동결 E1 교사 증류). 문헌상 불균형 해법 중 근거가 가장 강하고, 우리 실측(s821: EMM 37.60→48.68)도 같다. 게이트가 이것을 대체한다고 기대하지 않는다.
2. **모달별 보조 분할 헤드**(가벼운 1×1): 매 배치 모달별·창별 손실 ℓ_m 과 leave-one-out 손실 ℓ_{−m} 을 얻는다(dropout 이 반사실 배치를 이미 만든다).
3. **게이트 목표(외부 레이블 0)**: 창(16×16 토큰)마다 t_m = softmax_m(ℓ_{−m} − ℓ_full) — "이 창에서 이 모달을 빼면 얼마나 나빠지는가". 모델 자신의 손실에서 나오므로 언어·조건 라벨·depth GT 가 필요 없다. stop-grad 로 게이트만 CE 학습.
4. **게이트 입력**: 깊은 DINOv3 토큰만 쓰지 않는다. 얕은 LoRA 층 특징에서 계산한 **매개변수 없는 stop-grad 기술자**(모달쌍 고주파 에너지·위상 일치·교차 상관, 코사인 |f_a−f_b|) + 모달별 p_true 예측을 넣는다.
5. **학습 순서**: 학생(Q2) 수렴 → 게이트 단계 학습(직접 동시 학습은 라우터 붕괴 보고, 2609.29235). 게이트 하한 ε + EMA 로 요동·기아 방지(2608.24947).
6. 게이트 출력은 교차 모달 attention 의 key 스케일(또는 가중 평균)로 쓴다.

## 3. 사전 등록 게이트·반증 기준
- **1단계(학습 0, 먼저)** — 오라클 여유 프로브: Q2 s821 체크포인트로 창마다 "최선 모달 부분집합"을 고른 오라클 예측의 mIoU − 전 모달 mIoU. DELIVER val 과 조건별(모션블러·노출·야간·안개·LiDAR jitter·event 저해상도)로 잰다. **오라클 여유 < 1.0 mIoU 이면 게이트가 얻을 것이 없으므로 P55 중단**(DELIVER 는 D≈L 중복이라 작을 수 있다 → MUSES 야간·안개에서 따로 잰다).
- **2단계** — 게이트 학습 후 치환 검정: 게이트 입력을 창 사이에서 섞으면 성능이 떨어져야 한다. 기준: 모션블러·저노출 부분집합에서 치환 격차 ≥ 0.5 mIoU, RGB 결측 EMM 에서 ≥ 2 mIoU, 모션블러·저노출 프레임의 평균 RGB 가중이 clean 대비 ≥ 30% 낮음.
- **반증**: 오라클 여유 > 2 인데 치환 격차 < 0.3 이면 "게이트 목표 불일치" 가설은 틀렸고, 남은 원인은 event·LiDAR 와 depth 의 표현 공선성(게이트로 못 고침)이다.
- clean: legal v2 24클래스 Δ vs Q2 ≥ −0.3(Q3 는 −1.31 로 실패했다).
