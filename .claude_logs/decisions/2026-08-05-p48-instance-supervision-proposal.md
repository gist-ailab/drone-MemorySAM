# P48 — 쿼리 경로 인스턴스 감독 (Instance Supervision) 제안 (2026-08-05)

> 판정·설계 = opus 세션. 근거는 전부 실측 또는 arXiv 원문. 게이트는 **사전 등록**이며 학습 시작 후 수정 금지.

## 0. 한 줄 요약

쿼리 경로가 **dense의 복제**로 수렴했다(실측: 제거해도 픽셀 98.9% 동일, 순기여 −0.09). 원인은 쿼리가 받는 유일한 감독이 *semantic*이고 그건 dense가 이미 푸는 문제라는 것이다. **dense가 원리적으로 풀 수 없는 과제(인스턴스 분리)** 를 쿼리에 직접 감독으로 부여해 중복을 깨고, PQ의 병목인 RQ 붕괴(44.51)를 복구한다.

**D4가 이번 제안의 결정적 근거다.** 이전에는 "쿼리에 인스턴스 감독을 붙이면 좋을 것"이라는 정성적 기대였으나, 지금은 **쿼리가 왜 놀고 있는지의 기제**가 측정됐다 — 중복이다. 인스턴스 감독은 "쿼리를 살리는" 처방이 아니라 **"중복을 구조적으로 불가능하게 만드는"** 처방이다.

## 2. 설계 — 전 항목 토글

| 토글 | 변경 | 근거 키 | 기본값 |
|---|---|---|---|
| **P48-a** `inst_targets` | `m2f_head` 타깃을 클래스단위 → **connected-component 인스턴스 단위**. stuff는 기존대로 클래스 병합 | D2·D3 + MaskFormer | **on** |
| **P48-b** `inst_matcher` | Hungarian matching을 인스턴스 타깃에 맞게 확장(기존 matcher 재사용, 없으면 추가) | D3 | on (a의 종속) |
| **P48-c** `task_token` | semantic/panoptic 모드를 1개 학습 토큰으로 구분, 쿼리 하나 추가 | OneFormer | **off** (2차) |

### 🔴 불변 제약 — semantic 경로를 건드리지 않는다

현재 헤드라인 지표는 **mIoU**이고 MUSES val 82.58 / DELIVER val 67.74가 걸려 있다. 따라서:

- **dense 경로는 기존 semantic 손실을 그대로 받는다.** 변경 없음.
- **쿼리는 인스턴스 감독을 추가로 받는다.** 기존 semantic 기여(`q_scaled`)는 유지 — 제거하지 않는다(제거하면 D4의 −0.09만큼만 움직이므로 안전하지만, 굳이 두 변수를 동시에 바꾸지 않는다).
- **추론 semantic 경로는 배선 변경 0.** 스모크에서 `|Δ|max == 0` 을 assert한다.

이는 실패-키 **키1**("새 모듈은 주 손실을 직접 받아야 한다")을 위반하지 않는다 — 인스턴스 손실이 쿼리에 **직접** 걸리며, zero-init 잔차로 얹는 구조가 아니다.

### 학습 0으로 선행 가능한 측정 (구현 전에 할 것)

1. ✅ **완료 (2026-08-05)** — MUSES는 D2′로 검증됨(위 표). 🔴 **DELIVER는 P48 대상에서 제외한다**: DELIVER의 인스턴스 주석(`coco_*.json`)은 **`Human`/`Vehicle` 2개 카테고리뿐**이라 25개 시맨틱 클래스(Pedestrian/Cars/TwoWheeler/Bus/Truck)와 정렬되지 않는다. 인스턴스 감독을 걸 수는 있으나 클래스 해상도가 맞지 않아 PQ 학습에 쓸 수 없다. → **P48은 MUSES 전용**, S3의 데이터셋 선택은 편의가 아니라 제약이다.
   ⚠️ 부수 기록: DELIVER semantic GT를 connected-component로 세면 43.89 inst/img가 나오나 실제 COCO 주석은 3.33 inst/img — **13배 과대**(CARLA 마스크 파편화). **CC를 인스턴스 수 대용으로 쓰지 말 것.**
2. 🔴 **query-only semantic mIoU** — 현행 ckpt에서 dense를 끄고 쿼리만으로 semantic을 뽑는다. D4는 "쿼리를 빼도 안 변한다"를 보였지만 **"쿼리 단독으로 얼마나 하는가"** 는 아직 모른다. 두 값의 조합이 진단을 확정한다:
   - 쿼리 단독이 dense와 비슷 → **완전 복제**. 인스턴스 감독의 여지가 크다.
   - 쿼리 단독이 크게 낮음 → 쿼리는 dense를 보정만 하는 약한 경로. 인스턴스 감독 전에 **쿼리 용량 자체를 키워야** 한다.
   ⚠️ 현재 `module_ablation.py`에 dense-off 토글이 **없다**. 이 측정을 위해 토글 1개 추가가 필요하다(추론 전용, 학습 무영향).

### Falsifiable 예측 (2026-08-05 상향 — 이전 게이트는 무효였다)

> **things PQ가 33.6을 넘지 못하면 인스턴스 감독은 효과가 없는 것이다.**

**⚠️ 최초 등록한 게이트 "30 이상"은 검정력이 없었다.** D2′가 계산한 **클래스단위 타깃 하의 things PQ 상한이 33.6**이므로, 30은 *현행 타깃 구성 안에서도 도달 가능한 값*이다. 그 게이트는 통과해도 "인스턴스 감독이 기여했다"를 증명하지 못한다 — 학습이 나아졌을 뿐일 수 있다.

올바른 검정선은 **상한 자체를 넘는 것**이다. 33.6은 "예측 마스크 1장이 GT 인스턴스 k장 중 최대 1장만 매칭된다"는 구조적 제약에서 나오므로, 인스턴스 타깃이 실제로 작동할 때만 넘을 수 있다.

- **33.6 초과** → 타깃 구성이 천장이었다는 D2 확정, P48 성립.
- **18.33~33.6 사이** → 개선은 있으나 **기제 미확정**. 학습 개선과 구분되지 않으므로 성공으로 보고하지 말 것.
- **18.33 근방 정체** → **D2 철회**, 진단을 쿼리 용량·매칭 품질로 옮긴다.

※ 33.6 = things RQ 상한 42.5(FP=0·매칭 상한만) × 측정 SQ 0.79. FP를 감안하면 실제 상한은 이보다 낮으므로 33.6은 **보수적(우리에게 불리한) 선**이다.

## 4. 노벨티 포지셔닝 — 🔴 주장하지 않는다

**인스턴스 감독 자체는 표준 기법이다**(MaskFormer 계열 전부). P48은 novelty가 아니라 **정합화(버그 수정에 가까움)** 다 — 우리가 panoptic head를 달아놓고 semantic 타깃으로 학습시키고 있었다.

논문에서의 서술 방침:
- "panoptic 확장" 절에서 **구현 사실로만** 기술하고 기여로 주장하지 않는다.
- PQ 수치는 "우리 방법이 semantic 전용이 아니라 panoptic으로도 동작한다"는 **범용성 증거**로만 쓴다.
- 리뷰 방어: PQ가 SOTA에 못 미쳐도 문제되지 않는 위치에 둔다. 헤드라인은 mIoU를 유지한다.
