# P56-B·C 설계서 — modality-aware 융합 구조 (2026-09-30, 생각정리)

user 승인 2026-09-30: "B, C 설계 착수해, 의존도 분석도 추가해". 구현·기동은 이 설계서 검토 후 별도 승인.

## 0. 이 설계가 답해야 하는 것

논문의 중심 주장(user 방향 2026-09-30) = MemorySAM(순차 메모리 attention)·MM SAM-adapter(RGB 고정 주입)·DGFusion(외부 prior 조건화)과 구별되는 **modality-aware 융합 구조**. 생각정리의 작업 정의: 융합 계산이 토큰마다 ① 어느 센서에서 왔는지(센서별 LoRA) ② 센서가 잰 물리량(거리) ③ 얕은 블록 통계로 추정한 센서 상태 ④ 센서 간 일치도 에 따라 달라지고, 그 사용법을 결측·충돌 학습(Q2·P56-A)으로 배운다. P56-A 는 ④를 학습으로만 만들므로 구조 기여는 **B(②)·C(③)** 가 맡는다.

바탕 = Q2 레시피(두 패스 + 동결 E1 교사 증류, 강건 축 3시드 통과). A 가 통과하면 A 포함 레시피가 바탕.

## 1. P56-B — 거리 조건화 교차 attention (range-conditioned cross-modal attention)

### 1.1 동기(실측)
- 우리 주 손실 요인은 원거리 얇은 객체(찾고도 못 그린 비율 거리3 구간 0.44 vs 기준선 0.25). 손실 재가중(R2)·경계 신호(R1)·세부 가지(E17) 셋 다 실패 → 헤드 쪽 처방은 소진.
- 융합 attention 은 위치 정보가 전혀 없다(`fusion.py:245-266`: LayerNorm 뒤 plain SDPA). 한 센서의 토큰이 다른 센서에서 "같은 물체"를 찾을 근거가 특징 유사도뿐이라, 멀고 작은 물체(토큰 몇 개)는 배경 토큰에 묻힌다.
- Depth·LiDAR 는 값 자체가 거리다. 외부 레이블이 아니라 센서 측정치이므로 "외부 prior 불사용" 원칙과 충돌하지 않는다.

### 1.2 기제
교차 attention 의 로짓에 **거리 차이 편향**을 더한다. query 토큰 i(센서 a)와 key 토큰 j(센서 b)의 거리 추정 r_i, r_j 에 대해

    logit_ij += −λ_h · |log r_i − log r_j| / σ_h   (head h 마다 λ_h ≥ 0, σ_h 학습, λ 초기 0 → 항등에서 출발)

- r 은 **장면의 거리**이므로 센서와 무관하게 같은 토큰 위치에 하나다. 출처 우선순위: depth 맵의 토큰 평균 → 없으면 LiDAR 투영의 유효 화소 평균 → 둘 다 없으면 편향 0(마스크). 열화 패스에서 depth 가 결측·열화되면 자동으로 LiDAR 로 넘어가거나 꺼지므로, "거리 정보가 있을 때만 쓴다"가 학습 표본으로 들어간다.
- 구현 위치: `CrossModalAttentionLayer.forward` 의 `attn_mask` 는 지금 (B,1,1,Nk) 키 편향만 받는다(`fusion.py:258-262`). (B,h,Nq,Nk) 전체 편향을 받도록 넓히고, 거리 편향 텐서는 `CrossModalFusion.forward` 에서 토큰 거리 맵으로 한 번 만들어 두 층에 넘긴다. 메모리: 2304×6912×8 head × bf16 ≈ 255MB/샘플, BS1 에서 허용(A100 40GB, Q2 17.7GB 사용).
- 선택 B-2(같은 카드 안 토글): 거리의 사인 인코딩을 query·key 에 더하는 "거리 위치 임베딩". 편향 방식(B-1)이 주 후보, B-2 는 ablation.

### 1.3 왜 이것이 modality-aware 인가
attention 이 "어느 거리대의 토큰끼리 묶을지"를 Depth·LiDAR 가 잰 값으로 정한다. RGB 특징만 보던 융합에 기하 채널이 들어오며, 거리 채널이 없어지면 계산이 스스로 원래대로 돌아간다(편향 0). DGFusion 의 depth 토큰은 depth **정답 감독**으로 만든 특징을 융합에 넣는 것이고, 여기서는 감독 없이 측정값 자체를 attention 의 기하로 쓴다.

### 1.4 사전 등록 게이트(40에폭 스크린, 시드 821·902, Q2 또는 Q2+A 짝)
- G1 clean: 24클래스 Δ vs 짝 ≥ −0.3
- G2 표적: 깊이 구간 47~111m·111~255m mIoU 평균 Δ ≥ +1.0 **또는** 얇은 객체 4클래스 Δ ≥ +1.5 (2시드 평균)
- G3 결측 안전: depth 결측 조합(EMM)에서 짝 대비 Δ ≥ −0.3 (거리 채널이 사라져도 무너지지 않음)
- 반증: G2 미달이면 "기하 위치 정보 부재"가 원거리 손실의 원인이라는 가설 폐기, B-2 로 넘어가지 않고 종료
- 조기 규칙: ep20 학습기 val 이 짝 ep20 대비 −1.0 미만이면 중단
- 비용: A100 1장 × 약 3.5일 × 2시드(+ B-2 1시드)

### 1.5 코드 변경 범위
`semseg/models/reliadino/fusion.py`(CrossModalAttentionLayer 편향 형상 확장, 거리 편향 생성), `model.py`(토큰 거리 맵: depth·LiDAR 입력에서 stride-16 평균, 결측 마스크), config `MODEL.FUSION.RANGE_BIAS.{ENABLE, SOURCE, INIT_LAMBDA, LOG_SPACE}`. 하네스 동결 8파일은 건드리지 않는다. off 이면 forward·state_dict 동일(기존 규약).

## 2. P56-C — 센서 상태 조건부 LoRA 전문가 혼합 (state-routed shared/per-sensor LoRA)

### 2.1 동기(실측)
- E-LoRA 9칸: depth 절반 열화에서 완전 공유 LoRA(arm B)는 손해 −6.82, 센서별(arm A) −15.77, 정적 잔차 합(arm C) −11.94 → 둘의 장점을 **고정 비율**로는 못 합쳤다.
- E1-shared 3시드: depth 열화 저하 비율 0.47(통과)이지만 clean 24클래스 −0.24, 얇은 객체 −2.10, 시드 분산 증가.
- Q1c·Q1d: 얕은~중간 블록(상대 깊이 10~50%) 특징이 저수준 변화(밝기·질감·열화 흔적)를 담는다. 합성 라벨 감독은 실패했지만 **입력**으로는 유효.

### 2.2 기제
`SharedLoRAQKV`(shared + 잔차, `encoder.py:192`)를 확장해 **토큰별 혼합 계수**를 둔다.

    ΔW x = α(x) · shared_delta(x) + (1 − α(x)) · sensor_delta_m(x),   α ∈ [0,1]

- α 는 라우터가 낸다: 입력 = 해당 센서의 블록 k(상대 깊이 0.25 = 블록 6) 토큰 특징(stop-grad) + 센서 임베딩. 라우터 = LN → Linear(1024→64) → GELU → Linear(64→1) → sigmoid, 초기 편향 0(α=0.5). 블록 6 이후 블록들에만 혼합을 적용하고 블록 1~6 은 센서별 LoRA 고정(라우터 입력이 나오기 전이므로).
- 라우터 파라미터는 센서 간 공유(센서 임베딩으로 구분), 약 7만 개. LoRA 는 공유 r8 + 센서별 r8.
- 붕괴 방지: α 의 토큰 간 표준편차가 0.05 미만으로 4에폭 이상 유지되면 정적 혼합으로 판정(종료 규칙). 정규화는 두지 않는다(P55 교훈: 목표 없는 게이트는 상수로 앉는다 → 여기서는 열화·충돌 학습 표본이 α 를 움직일 유인).
- 선택 C-2: α 를 토큰별이 아니라 센서별 스칼라(이미지당)로. 표현력은 낮지만 안정. C-1 이 붕괴하면 C-2.

### 2.3 왜 이것이 modality-aware 인가
어댑터의 계산이 "이 센서가 지금 어떤 상태인가"에 따라 토큰마다 달라진다. 센서가 정상이면 센서별 전문가(clean 정확도), 열화되면 공유 전문가(교차 센서 공통 표현)로 기울도록 학습 표본이 가르친다. Soft-MoE LoRA(우리 SAM2 계보)와 다른 점: 전문가가 "센서별 vs 공유"로 의미가 고정돼 있고, 라우터 입력이 얕은 블록 통계로 제한돼 해석 가능하다.

### 2.4 사전 등록 게이트
- G1 clean: 24클래스 Δ vs 짝 ≥ −0.3, 얇은 객체 4클래스 Δ ≥ −1.0
- G2 강건: depth 부분 열화(RMM r .25/.5/.75) 실제 저하가 짝의 0.6배 이하 **그리고** RGB 부분 열화 저하도 0.8배 이하(공유 LoRA 가 depth 한 모달에만 듣던 한계를 넘는지)
- G3 라우터 생존: α 토큰 표준편차 ≥ 0.05 이고 조건별 평균 α 가 clean 대비 악조건에서 유의하게 다름(Mann-Whitney p<0.01)
- 반증: G2 미달 또는 G3 붕괴면 "상태 조건부 혼합" 가설 폐기, E1-shared(정적 공유)와 센서별 중 택일로 회귀
- 비용: A100 1장 × 약 3.5일 × 2시드

### 2.5 코드 변경 범위
`encoder.py`(SharedLoRAQKV 에 α 입력 경로, 블록 6 특징 hook 재사용 = `P55BlockCapture` 규약), `model.py`(라우터 모듈·로깅), config `MODEL.LORA_MODE: state_routed`, `MODEL.LORA_ROUTER.{BLOCK_FRAC, HIDDEN, PER_TOKEN}`.
