# P53 후보: 고해상도 세부 가지(Detail Branch) — 얇은 객체 병목 직격 (2026-09-17)

> **user 결정(2026-09-17)**: 논문 1차 주장 렌즈 = **전 모달 융합 계열 1위**(같은 모달리티 집합을 쓰는 방법 안에서 세 벤치 1위). 이 렌즈의 약점 = DELIVER 4모달 1위(56.99)가 **단일 런**이고 같은 레시피 5시드 평균(53.83)·E1/E13 확정 평균(54.9~55.1)이 DGFusion 56.71에 못 미친다. 시드 평균으로 1위를 주장하려면 DELIVER test에서 **+1.6~1.8**이 더 필요하다. 이 문서는 그 이득을 어디서 찾을지에 대한 제안이다.

## 1. 진단 — 이득은 얇고 작은 객체에 남아 있다

카드 프로그램의 클래스별 분해(§5-2·§5-30)와 DGFusion 공식 설정 재현(80k, test 55.68)의 대조:

| 클래스 | 우리(E13 확정 시드1 / E1) | DGFusion 재현 | 차이 | 성격 |
|---|---|---|---|---|
| Pole | 47.2 | 59.0 | **−11.8** | 얇음 |
| TrafficLight | 22.6 | 37.5 | **−14.8** | 작음 |
| Pedestrian | 71.2 | 83.1 | **−11.9** | 작음·가늘음 |
| Static | 35.6 | 43.3 | −7.7 | 작음 |
| RailTrack | 68.5 | 50.4 | +18.1 | 큰 영역 |
| Wall / Water | 14.4 / 10.8 | 2.2 / 4.1 | +12.2 / +6.7 | 큰 영역 |

- 우리는 **큰 영역·모호한 경계 클래스에서 이기고, 얇고 작은 객체에서 진다.** 네 클래스의 손실 합만 −46점, 25클래스 평균으로 **−1.85**다. 렌즈의 요구치(+1.6~1.8)와 크기가 맞는다.
- 카드 결과의 방향도 같다: 결합 카드 E12에서 유일하게 가산이 작동한 영역이 얇은 객체(TrafficLight +13.07·Pole +3.33)였고(§5-9), 얕은 탭 E14는 TrafficLight를 −16 잃어 폐기됐다(§5-30). 즉 얇은 객체는 **어느 층의 토큰을 읽느냐가 아니라 토큰 격자 밖의 정보**가 필요하다.

## 2. 왜 지금 구조로는 못 푸는가

- 백본은 stride-16 토큰(768² 입력에서 48×48)만 내고, `SimpleFPN`(encoder.py)은 그 한 맵을 ConvTranspose로 stride-4·8까지 **늘려 쓴다**. 1/16 격자에서 사라진 세부는 복원되지 않는다.
- **입력 해상도를 1024로 올려도 test 이득이 없었다**(registry P46@1024 두 시드 54.85/54.55 vs 768 학습 54.39±0.76). 격자를 촘촘히 해도 안 되는 것은 세부 전용 경로가 없기 때문이다.
- SOTA(MM SAM-adapter)는 ViT 옆에 ConvNeXt-S 측면 가지를 두어 1024 세부를 따로 뽑는다(2모달). 우리는 4모달 전부에 같은 역할의 가지를 붙이되 훨씬 가볍게 간다.

## 3. 설계 — MODEL.DETAIL_BRANCH (단일 변수, 기본값 off)

| 항목 | 값 |
|---|---|
| 입력 | 백본에 넣는 것과 같은 전처리 텐서, 모달별 |
| 스템 | conv3×3(s2,32)→GN→GELU→conv3×3(s2,64)=stride-4 → conv3×3(s2,128)=stride-8, 1×1로 fpn_dim(256) 투영. 목표 파라미터 ≤ 1M |
| 모달 처리 | `shared_stem`(기본): 스템 공유, 모달별 1×1 투영만 분리 → 합산 / `per_modal`: 스템도 분리 |
| 주입 | FPN pyramid의 stride-4·stride-8 레벨에 **게이트 잔차** `pyr += tanh(g)·detail`, g init **0.1**(zero-init 금지 규칙) |
| 공존 | TAPS(E1)와 독립(TAPS는 stride-16 토큰에서, 세부 가지는 입력에서) — E17 = E1 레시피 + DETAIL |
| 메모리 | 모달별 순차 계산·누적, checkpoint 금지(ISSUE-027). 768² BS1 24GB 진입이 조건 |

구조 사다리(감사 문서 §3.6)와의 관계: S1(4탭)·S2(LoRA 확장)·S3(블록 간 교환)·S4(부분 FT)·S5(비RGB 별도 인코더)는 전부 **토큰 격자 안**의 변경이다. 세부 가지는 그 축과 직교하는 "격자 밖 정보" 축이며, S5의 경량판으로 볼 수 있다(S5는 비RGB만·ConvNeXt-S, 이것은 전 모달·1M 스템).

## 6. 리스크

- 세부 가지가 RGB 세부에 치우쳐 야간·안개에서 손해를 낼 수 있다 → G3가 잡는다. 모달별 1×1 투영이 센서 가중을 배우게 둔다.
- 얇은 객체 손실이 세부 부재가 아니라 **손실 함수(OHEM CE)의 클래스 불균형** 탓일 수 있다 → E17이 G2를 못 넘으면 다음 단일 변수는 손실 쪽(얇은 클래스 가중·경계 손실)이다.
- MUSES·MCubeS 이식은 E17 통과 후에만(모달 채널·해상도가 달라 스템 in_channels 확인 필요).
